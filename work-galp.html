Overview

Unifying a fragmented
visual language

Galp's digital products — web apps and mobile apps — were using inconsistent icon and component styles. Different products had sourced icons from different libraries, resulting in a disjointed visual experience that undermined brand cohesion.

The challenge was analysing all components in use across the ecosystem and unifying them into one consistent system that could serve every product and platform.

I created a unified iconography system with four distinct styles and a UI component library — buttons, badges, switches, sliders, tabs, and cards — all documented in a comprehensive style guide. The guide covered construction rules, interaction states, usage guidelines, and strict naming conventions, giving every team a shared visual vocabulary.

The result brought visual consistency across Galp's web and mobile products, eliminated duplicate or conflicting components, and provided a scalable foundation for future growth.

Problem & Goals

A fragmented
icon landscape

Galp's products had grown organically, and each team had solved iconography on its own terms. Icons were pulled from different open libraries, drawn at different sizes, and built on incompatible stroke and grid conventions. The same concept — search, settings, account — could appear three different ways across two screens.

This created visible inconsistency for users and hidden cost for teams: duplicated effort, no single source of truth, and no rules for adding new icons without making the problem worse.

The goals were clear:

Unify every icon in use into one coherent visual language.
Document construction, usage, and naming so any team could contribute correctly.
Scale the system across web and mobile without re-introducing fragmentation.

Success meant teams reaching for one library by default — and trusting it.

Research & Discovery

Auditing what
already existed

Inventory

I started by collecting every icon in active use across Galp's web and mobile products. Cataloguing them side by side made the scale of the problem concrete — overlapping concepts, conflicting styles, and orphaned icons no longer tied to any live feature.

Patterns & gaps

Mapping the inventory by function revealed the real coverage needed and exposed gaps where teams had improvised. It also surfaced the recurring contexts — dense UI, marketing, onboarding — that would later justify four distinct icon styles rather than one.

The discovery work turned a vague sense of “our icons look messy” into a defensible brief: a known set of concepts to cover, a known set of contexts to serve, and clear evidence for the rules the system would need to enforce.

Icon Styles

Four Styles,
One System

Each icon style was designed for a specific context. The system provides clear guidance on when to use each style, ensuring consistent application across products and platforms.

☐
Outline
Clean line icons for navigation, toolbars, and compact UI. Optimised for small sizes with consistent 1.5px stroke weight.
◼
Filled
Solid icons for active states, emphasis, and high-density interfaces. Strong visual weight for selected or highlighted elements.
◧
Duotone
Two-tone icons for marketing materials and feature highlights. Combines line and fill for visual richness at larger sizes.
▣
Flat
Simplified flat icons for illustrations, onboarding, and decorative contexts. Minimal detail for maximum clarity at scale.
Component Library

Beyond icons —
a component system

The system reached past iconography into the interactive building blocks of Galp's products. Each component was documented with its full range of interaction states — default, hover, pressed, focus, and disabled — so behaviour stayed consistent wherever it appeared.

Buttons
Primary and icon-and-text buttons with documented Default, Hover, Pressed, Focus, and Disabled states.
Badges
Fill and outline badges plus icon badges, in small, default, and medium sizes for counts and notifications.
Switches & Selectors
Toggles, checkboxes, and radios with default, checked, selected, and disabled states.
Sliders
Range sliders and interval sliders for filtering and value selection across the products.
Tabs
Horizontal and vertical tab patterns with a clear active state for sectioned navigation.
Cards
Stat cards, product cards, and feature cards — the containers used to surface accounts, credit, and offers.
Construction

Grid & Rules

All icons are constructed on a 24×24px grid with a 2px safe zone. Key shapes — circles, squares, rectangles — are optically corrected to appear visually consistent rather than mathematically identical.

Stroke width is fixed at 1.5px for outline icons. Corner radii follow a consistent 1px rule for inner corners and 2px for outer corners, creating a subtle but uniform roundness across the set.

Each icon follows strict alignment rules: centred within the grid, optically balanced, and tested at both 16px and 24px to ensure readability at all target sizes.

The construction guidelines document covers every rule — from minimum line gaps to angle standardisation — ensuring that any designer contributing to the library produces icons that feel native to the system.

Design Decisions

Decisions &
rationale

Every choice in the system was made to reduce ambiguity for the people using it. A few decisions shaped the rest.

Four styles, not one. Rather than force every context into a single look, the system offers outline, filled, duotone, and flat — each mapped to a clear use case. This prevented teams from going off-system when one style didn't fit their context.

Optical correction over maths. Shapes are balanced by eye, not by pixel-perfect geometry, so icons read as consistent at the sizes users actually see them.

A fixed grid and stroke. A 24×24 grid, 2px safe zone, and 1.5px stroke gave contributors hard constraints — the fastest way to keep a growing library coherent.

Naming as a feature. A strict, function-based naming convention made icons discoverable and made the library safe to extend. Good names were treated as part of the design, not an afterthought.

Process

How It Was Built

01
Audit & Inventory
Audited all existing icons across Galp's digital products. Identified inconsistencies in style, sizing, and stroke weight. Catalogued the full icon needs for all platforms.
02
Grid & Principles
Established the construction grid, stroke rules, corner radii, and optical correction principles. Defined the four style variants and their appropriate usage contexts.
03
Core Set Design
Designed the initial set of 200+ icons across all four styles. Each icon was tested at multiple sizes and across light and dark backgrounds for readability.
04
Naming & Organisation
Created a systematic naming convention and category structure. Icons are grouped by function — navigation, actions, objects, status — for easy discoverability.
05
Usage Guidelines
Documented comprehensive usage guidelines including sizing rules, spacing recommendations, colour application, and do's and don'ts for each style variant.
06
Handoff & Integration
Delivered as SVG exports, Figma component library, and developer-ready icon font. Integrated directly into Galp's existing OutSystems design system.
