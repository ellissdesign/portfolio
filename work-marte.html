Overview

Clear task
management

Marte is a portal for analysing and managing tasks. The existing system was complex and difficult for workers to navigate — creating friction in daily operations and reducing productivity.

The challenge was transforming a cluttered, confusing interface into a clear, modern environment that workers could use and understand immediately without extensive training.

I designed a clean, structured web portal that simplified task workflows and made information hierarchy immediately apparent. The interface prioritises clarity over density — every element earns its place on screen.

Using OutSystems patterns as the component foundation ensured consistency with existing internal tools while introducing a significantly improved user experience.

Problem & Goals

A tool that
got in the way

Marte's existing portal had grown complex and hard to navigate. Workers faced information overload, unclear hierarchy, and too many steps to complete everyday actions. The tool meant to help people manage their work was itself a source of friction — slowing daily operations and adding to the learning curve for new staff.

The redesign had to make the portal feel obvious: something a worker could pick up and understand immediately, without training.

The goals were focused:

Clarify the interface so the important information is always apparent.
Simplify task workflows and reduce the steps to common actions.
Modernise the look and feel without breaking consistency with existing internal tools.
Improve productivity by lowering cognitive load.

Built on OutSystems patterns to stay consistent and efficient to deliver.

Research & Discovery

Watching the
real workflow

Worker interviews

I interviewed the people who used the portal every day and mapped their existing task workflows end to end. Seeing the work as they experienced it surfaced exactly where the tool fought them rather than helped them.

Pain points

Three problems dominated: information overload, unclear hierarchy, and too many steps to complete common actions. Naming them precisely turned a vague “it's confusing” into a concrete list the design could answer to.

Discovery reframed the brief around clarity. Every later decision — the restructured hierarchy, the progressive disclosure, the generous whitespace — traces directly back to a pain point observed in this phase.

Design Decisions

Decisions &
rationale

Each decision served one aim: make the right information and the next action obvious. A few choices shaped the rest.

Clarity over density. Every element has to earn its place on screen. Generous whitespace and strong typography keep each view scannable instead of overwhelming.

A clear mental model. The structure was rebuilt around tasks, projects, and analytics, with progressive disclosure so detail appears only when it's needed.

Reusable components. Task cards, status filters, priority badges, and data tables were designed as a consistent set — predictable for users and efficient for developers.

OutSystems as the foundation. Building on existing component patterns kept the portal consistent with internal tools and fast to ship.

Process

How It Was Built

01
Research
Interviewed workers and mapped existing task workflows. Identified the key pain points — information overload, unclear hierarchy, and too many steps to complete common actions.
02
Information Architecture
Restructured the task hierarchy and navigation. Designed a clear mental model — tasks, projects, and analytics — with logical groupings and progressive disclosure.
03
UI Design
Created a clean, modern dashboard and task views using OutSystems patterns. Focused on whitespace, clear typography, and visual hierarchy to reduce cognitive load.
04
Component Design
Designed reusable UI components — task cards, status filters, priority badges, and data tables — all built on OutSystems patterns for development efficiency.
05
Prototyping
Built interactive prototypes for the key task management flows — creating, assigning, tracking, and completing tasks — and validated with stakeholder walkthroughs.
06
Delivery
Delivered Sketch files with complete component specs aligned to OutSystems patterns. Included guidelines for data density, empty states, and responsive behaviour.
