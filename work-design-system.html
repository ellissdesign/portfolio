Overview

One system.
Six identities.

Designing a single component library that can faithfully represent six distinct brand identities — each with their own visual language, typography, colour philosophy and interaction patterns — without duplicating components or fracturing the system.

The challenge was architectural: how do you build once and deploy everywhere, while preserving the identity of each brand so thoroughly that no user ever notices they're looking at the same component underneath?

The answer was a three-layer Figma variable architecture — Primitive, Semantic, and Component — where swapping a single brand mode cascades through every token in the system, updating 100% of components instantly and consistently.

This case study documents the architectural thinking, the token structure, and the live interactive demo you can explore below.

Architecture

The Three-Layer
Token Model

Figma Variables are structured in three distinct collections, each serving a specific role. No layer can skip another — all references must travel the full chain from Primitive through Semantic to Component.

Layer 01 / Primitive
Raw Values
The foundation. Pure, literal values — hex codes, pixel values, type sizes. No context, no meaning, no aliases. One source of truth for every value in the system.
color/blue/500 = #0A56E8
color/red/500 = #CC1A1A
color/black/900 = #0A0A0A
spacing/04 = 16px
radius/none = 0px
Layer 02 / Semantic
Brand Aliases
The brand layer. Each brand is a separate Mode in this collection. Tokens describe intent — "primary", "surface", "on-primary" — and each mode resolves to different Primitive values.
[Brand A] primary → blue/500
[Brand B] primary → red/500
[Brand C] primary → black/900
[Brand A] surface → white/000
[Brand B] surface → grey/050
Layer 03 / Component
Component Tokens
The topmost layer. Every component property — button background, border colour, icon colour — maps to a Semantic token. Never a Primitive directly.
button/bg → semantic/primary
button/fg → semantic/on-primary
badge/border → semantic/primary
nav/accent → semantic/primary
input/focus → semantic/primary

Process

How It Was Built

01
Brand Audit & Tokenisation
Analysed all brand identities side by side — extracting shared structural patterns while preserving individual visual languages. Translated brand guidelines into token schemas.
02
Primitive Layer Build
Established the full colour scales, spacing, typography, and radius values in a shared Primitive collection. Strict naming conventions enforced from day one to prevent drift.
03
Semantic Layer & Modes
Each brand was added as a mode in the Semantic collection. Intent-based token names (primary, surface, on-primary) ensure components never need to know which brand they're rendering.
04
Component Architecture
Components built once, pointing exclusively to Semantic tokens. No hardcoded primitives, no brand-specific overrides inside components. Every brand swap is automatic.
05
Tokens Studio & Handoff
Tokens exported via Tokens Studio for Style Dictionary consumption. Engineering teams receive a single JSON that drives all six brand themes with no manual intervention.
06
Accessibility Validation
Every brand mode validated independently for WCAG AA contrast ratios. Colour pairings were tested across all component states — rest, hover, focus, disabled — for all six identities.
